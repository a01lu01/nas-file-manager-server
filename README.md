# NFM Server

Optional NAS companion service for NAS File Manager: server-side file operations, upload finalization, and video sharing.

**NFM Server 是 NAS 文件管理器的可选配套服务，部署在用户自己的 NAS 或文件宿主上。当前处于设计阶段，仓库尚无可运行服务、正式镜像或部署命令。**

## 计划解决的问题

将大量文件操作的调度放到 NAS 侧，减少手机与 NAS 之间逐项往返；为受限账号完成已授权上传，并提供具有稳定视频身份的轻量分享。

| 能力 | 计划范围 | 当前状态 |
| --- | --- | --- |
| 递归删除 | NAS 侧遍历、删除、核验及任务查询／取消 | 待实现，首批能力 |
| 目录复制 | 服务器侧完整任务、目标认领、不覆盖及结果核验 | 待实现，首批能力 |
| 受限上传收尾 | 提交本人预登记上传并清理本任务临时文件，独立授权 | 待实现，首批能力 |
| 视频变化识别 | 目录事件为主、日志辅助、非必要不补查 | 待实现，可独立关闭 |
| 轻量视频分享 | 稳定视频 ID、版本映射、规则自动与服务端手动换版 | 待实现，独立授权 |

未部署服务时，App 继续使用原有 SMB／WebDAV 能力。相册模式和设备端视频压缩由 App 处理，不依赖本服务；NAS 上不存在原片时只登记实际上传的压缩成品。

## 使用目标

- 管理员统一配置受信入口、NAS 认证后端、目录映射及按账号／组的授权规则。
- 同事沿用原 NAS 登录，验证条件成立后取得本人增强能力，无需逐人配置 Docker 或手工配对。
- 对外分享地址自动预填候选，管理员确认完整 HTTPS 地址一次，NAS 持久保存，所有同事统一使用。
- App 直接访问自己的 NAS，服务不依赖 NFM 公共账号、云端文件中转或公网发现服务。

自动发现、跨品牌认证和真实 NAS 权限兼容均需先验证，尚不是已支持能力。默认无特权容器、不挂载 Docker 控制套接字，也不通过容器高权限替代普通账号授权。

## 独立维护

本仓库维护服务端详细设计、后续源码、部署说明和服务端问题。App 仓库负责界面、原协议通道及客户端接入；两者通过明确的接口版本和能力检测保持兼容。服务端发布版本独立于 App，当前规划对应 App 1.1.0 的增强服务需求，不表示每次服务端更新都要求 App 升级。

后续计划提供固定版本容器镜像和 Compose 示例；候选平台为 Linux amd64／arm64，只有通过实际构建和宿主测试后才列入支持范围。许可证、技术栈、镜像发布和资源预算仍待冻结，当前未配置自动构建、Pages 或镜像发布流程。
