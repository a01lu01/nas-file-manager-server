# 服务设计与权限边界

设计基线：2026-11-10。以下均为已确认产品方向与待实现约束；当前只有文档。服务后续设计以本仓库为准，App 继续单独维护客户端接入和通用协议能力。

## 1. 职责与能力

App 通过经核验的 HTTPS 入口调用 NFM Server，由服务将完整任务留在 NAS 侧调度。文件执行后端先验证再选定：可使用能够落实该用户真实权限的本地挂载，或 NAS 本地按该用户身份建立的协议连接。用户名相同、能挂载目录或容器可写，都不能单独证明等效于 NAS 用户权限。

| 能力 | 执行边界 |
| --- | --- |
| 递归删除 | 核验用户与根范围，在 NAS 侧遍历、删除和确认；删除语义明确 |
| 目录复制 | 源／目标均授权，排他认领目标，复制与核验完整目录；内容不经手机中转 |
| 受限上传收尾 | 管理员明确委托提交本人预登记上传及清理本任务临时对象 |
| 视频事件 | 独立监控授权根，识别变化；事件不自动成为上传、删除或换版授权 |
| 分享及版本管理 | 创建分享、完全免登录／登记后／登录后观看、统计查询和管理映射分别授权，详见[视频分享设计](video-sharing.md) |
| API 中心 | 为自研 OA 提供列表、详情、HTTP 上传、下载和删除，复用根映射、权限、收尾与作业能力 |

同卷移动优先由 App 使用已验证的原生目录重命名，减少不必要扫描与核验；跨卷移动仍有复制、核验及源清理关卡，不把一次 MOVE 失败直接改为删除源。服务不预先保证比所有 WebDAV 原生目录操作更快，实际收益须对照测试。

## 2. 管理员配置与账号核验

1. 管理员配置入口、TLS、可信发现信息、固定 NAS 认证后端、根映射与账号／组规则。高级手工配置保留，普通同事不以输入配对码为默认步骤。
2. 发现只定位服务。需证明配置受部署者控制，并与当前 NAS、服务实例和可信 HTTPS 身份绑定，不能向任意“同 IP”或普通可写 JSON 宣称的服务转发 NAS 凭据。不扫描整个局域网、不依赖 NFM 公网目录。
3. 服务独立核验 NAS 身份，不信任 App 自称已登录、用户名或单独 HTTP 200。优先验证标准协议认证，并区分实名、匿名与访客。组同步仅在后端可靠提供组信息时启用。
4. 按规则为验证通过的账号发放绑定用户、客户端、实例和范围的独立可撤销令牌，不共用管理员令牌。现有 NAS 凭据仅在已建立可信绑定且策略允许时用于认证，不明文持久保存或进入任务／日志。
5. 账号、密码、组规则、根映射或实例变化时重新核验；撤销生效后拒绝新任务，活动任务按实际停止结果收尾。后台认证重试有界，避免反复错误尝试锁定账号。
6. 文件连接与增强状态分开：增强服务失败或不兼容不阻塞原 SMB／WebDAV 登录。自动免配对是目标，无法验证的部署继续使用原协议。

普通删除／复制按实际用户的 NAS 访问权限执行。容器服务身份不能替代每个用户的 ACL；唯一明确的代理例外是管理员单独授权的受限上传收尾，不扩展为通用删除／改名权。

## 3. 根映射与部署

- API 使用服务实例、授权根 ID 和相对路径，不向客户端开放任意宿主绝对路径。映射须经管理员确认与只读核对；同名目录存在不能单独证明映射正确。
- 每次修改重新检查根边界、保护路径、符号链接、对象身份和检查后变化的竞争，禁止绕到其他用户或宿主路径。App 的校验不能代替服务端校验。
- 挂载后端只挂载所需根；协议后端可不挂载文件内容。配置、任务、映射数据库及必要密钥使用持久卷和恢复方案，运行身份与 UID／GID／ACL 单独验证。
- 默认不需要特权容器、Docker 控制套接字或宿主根目录挂载；权限不足不能靠默认 root 运行规避。入口仅按管理员配置开放，公开分享读取与管理／写操作分离。
- Linux amd64／arm64 为候选架构。各 NAS 只记录部署差异，不恢复逐品牌文件任务 API；未经真实验证的宿主、远程挂载和认证后端不标为支持。
- 活动任务、队列、I/O、内存和持久记录均有界，避免挤占预览和传输；具体值以实现测试冻结。容器运行不自动意味着有断点恢复或完整 NAS ACL 支持。

## 4. 作业、幂等与失败回退

- 修改前与 App 的预览句柄收尾、路径互斥及活动传输协调。句柄未确认释放时不绕过条件强行操作。
- 持久受理后返回任务 ID，绑定已验证用户、客户端、实例、操作意图、源／目标及幂等标识。重复提交返回原任务，不重复删除或创建副本；任务查询／取消仍核验归属。
- 状态区分准备、执行、核验、停止中、已停止、成功、部分失败、结果待确认。只统计已确认项，未知总量不伪造百分比；取消不代表已删除内容可恢复。
- App 退出或切目录只结束订阅，不代表 NAS 作业已停；容器重启先恢复记录、核对未决对象，不能盲目重放写操作。记录过期或丢失不能回答“未执行”。
- 未配置、范围外，或已确认服务未执行时，可继续原协议，仍受原账号权限与管理员策略约束。自动通道切换每任务最多一次。
- 超时、断线、响应丢失、仍在运行或停止未确认时先查询原任务。取得未执行／已终止证据并核对归属后才回退，不允许两个执行通道同时处理同一目标。
- 部分删除只处理已确认剩余范围；部分复制先核验原任务终态、源版本和已认领目标。不能整树覆盖或重传；无法接续时保留部分结果并请求明确下一步选择。
- 复制保留空目录和目录层级，拦截复制到自身／子目录，沿用编号与排他不覆盖策略；复制完成不自动删除源。设备中转须明确同意并说明流量、空间与前台要求。
- 永久删除与回收站语义必须明确，容器直接删除不能假称进入 NAS 原生回收站。语义变化需用户确认；跨卷源清理另设身份、版本及窗口保护。

## 5. 受限上传收尾

目标：账号可以没有普通删除权限，但经管理员独立授权后完成自己的上传。数据仍由 App 通过 SMB／WebDAV 断点上传，不重写上传引擎。

1. **上传前登记**：绑定本人、连接／服务实例、根、目标、预期大小和专属临时对象。发送前排他创建或可信认领，并记录对象身份；不能凭 `.uploading` 后缀或客户端路径接管现存文件。旧版未登记上传继续原流程。
2. **原协议写入**：持久传输与流式上传均接入同一登记和归属规则；收尾任务与 App 任务关联。普通同事无需额外配对。
3. **停止写入与核验**：数据发完后释放相关写句柄，确认对象身份、大小、版本及冻结的完整性要求。仍在修改、链接越界或身份变化时不能提交，100% 已发送不等于成功。
4. **受限提交**：专用服务身份仅在明确目标根内代办本人任务，沿用同名编号与不覆盖规则。直到正式对象核验满足要求才成功；确认前展示“正在完成上传”，目标存在不能单独证明本任务完成。
5. **文件系统与权限**：优先验证临时区和目标同文件系统的提交；跨文件系统未验证时不启用该配置。正式文件属主与 ACL 继承单独核对，防止代办意外改变访问范围。
6. **取消与故障**：仅清理可证明属于本任务的临时对象。已提交正式文件不因取消自动删除；清理成功、失败、未知分别保存。重复提交、确认丢失或重启先查询原任务，App 不同时自行提交。

受限代办与普通删除／复制分别配置，服务凭据只留在 NAS。未授权或上传开始前服务不可用时回到原流程；原账号缺少重命名／相关删除权限时如实提示。已受理后的服务失联不能视为未执行。任务失败、权限拒绝、冲突、网络失败、未知结果及清理失败分别记录，临时文件保留须经核实。

## 6. 可选视频事件：非必要不补查

- 管理员限定监控根与来源，本地目录事件优先；合适条件下评估可取消的 SMB CHANGE_NOTIFY。远程挂载、事件范围与中断行为单独验证，不假设等同于本地目录。
- 递归监听初始化可能遍历子目录以建立监听，但不借此盘点或逐个读取所有历史视频。无事件、空闲、App 打开／登录不触发扫描，也不设定时全量巡检。
- 日志仅按游标增量辅助，来源与轮转兼容逐项核对；缺日志不意味着没有变化。普通事件不提供可信上传人，缺少任务／审计证据时标为未知。
- 同对象／版本的重复事件合并，过滤纯读取和自身操作循环；仅对候选执行有界元数据及媒体检查。后缀、一次稳定或关闭写入不单独证明完整上传，分段暂停和未完成文件保留未确认状态。
- 先重放可恢复的事件／日志；明确溢出、失效游标、无法重放的停机缺口、子目录注册窗口或挂载变化才补查受影响范围。单文件慢、解析失败或普通网络超时只影响该候选。
- 缺口不明时最多补查已配置监控根，低优先级、有界并发与预算，保留未覆盖范围；管理员可显式指定目录补查。正常运行目标为零无故补查，不承诺任何情况下零遍历或永不漏报。
- 监控不自动转码、删除、移动或接管其他软件临时上传；不长期持有妨碍改名的句柄。服务关闭监控不影响前三项操作、普通 NAS 连接或 App 相册。
- 此策略只约束变化发现，不省略用户发起删除／复制、上传完整性和写入结果核验。

## 7. 提示与诊断

新增管理界面、公开观看页、状态及辅助功能名称覆盖 `zh-CN / zh-HK / en`。稳定错误原因与参数由显示层翻译，避免仅保存某种语言的错误文本。

诊断关联脱敏的实例、任务、通道、阶段、取消和恢复结果；不导出真实地址、路径、文件名、凭据或分享访问凭证。管理所需原始映射与文件信息限制在经授权的服务数据中，与可导出诊断分开。资源上限和诊断故障不阻塞核心文件流程，实际验证见[路线图](roadmap.md)。

## 8. API 中心与 OA 集成

2026-11-12 将 API 中心纳入服务套件，提供文件列表、详情、上传、下载和删除入口。管理员可登记 OA 应用、配置目录和操作授权、管理应用凭据，并查看开发文档、调用记录和任务状态。

接入草案按 OA 后端使用独立应用凭据、绑定专用 NAS 执行身份编写。文件操作核验应用授权与实际 NAS 权限的交集，员工级权限映射在接入时确定。OA HTTP 上传增加流式文件接收入口，复用上传登记、完整性核验和正式提交流程。下载与删除复用读取／取消和作业语义，长操作通过原任务核对结果。

接口目录、上传／下载流程及验证安排集中在独立计划维护。[API 中心计划](api-center.md)

## 9. 分享访问方式与观看统计

2026-11-12 确认每条分享提供“完全免登录”“免登录但需要登记”“登录”三种方式，查询播放次数与时长，以及登记访客／登录账号的完播进度和播放时间。登记名称由访客填写，NAS 签发登记编号与观看凭证，同名记录按编号分别保存。观看会话绑定分享、资产版本及账号／登记访客／匿名归属，媒体读取按对应访问策略核验。

统计采用有效播放进展、真实经过时间与去重的媒体播放区间，覆盖倍速、多次续看、并发、换账号及版本切换。NAS 以有界队列、批量写入和聚合维护记录，统计页标记补报或上报中断。业务记录按专用授权查询，诊断导出使用脱敏字段。登录后端和指标默认参数按独立计划确定。[访问方式与观看统计计划](video-analytics.md)
