# 轻量视频分享与稳定映射设计

设计基线：2026-11-10。由 NFM Server 独立提供轻量视频分享，采用稳定逻辑视频 ID 与文件资产映射。改名及经确认的压缩换版尽量沿用同一分享链接；可靠规则自动替换，其余由服务端管理页手动处理。

当前为设计文档，尚无服务实现、真实分享链接或 NAS 视频转码引擎。现有 App 在设备本地压缩后上传成品，首次 NAS 资产就是成品；已有 NAS 视频后来换版另行处理。具体接口、规则证据／阈值、分享默认值和后端兼容仍待冻结。整体范围见[服务设计](design.md)与[路线图](roadmap.md)。

## 1. 已确认目标与现有压缩边界

- NFM App 通过已验证 NAS 身份请求 Docker 创建分享，Docker 签发并登记访问凭证，App 在创建成功后复制链接；接收方直接访问用户自己的 NAS，不依赖 NFM 公共账号或文件中转服务器。
- 分享绑定稳定逻辑视频 ID，文件名、路径、后缀与具体编码文件通过映射维护。更名和已确认的压缩换版更新映射，不要求同事重新创建或发送链接。
- 现有“压缩后上传”在设备端完成压缩，NAS 首次接收到的就是成品。首次登记该成品为新视频的初始资产，不虚构 NAS 上不存在的原片，也不将普通同名新上传自动当作换版。
- NAS 已有视频后来被压缩／替换时，才建立原视频与新 MP4 的版本关系。明确源任务或管理员已启用且完整通过的可靠规则可自动发布；其余结果进入 NAS 服务端待确认列表，由管理员手动替换，普通分享者继续使用原链接。
- 本项不自动触发 NAS 转码，不要求手机原片先上传，再下载或在 NAS 重压。未来若增加 Docker 转码执行器，其算力、编码器、输出策略另行确认，映射接口可承接结果。

## 2. 分享访问与管理员配置

链路为：`App 创建分享 → NAS 登记分享 → 复制固定链接 → 浏览器播放页 → 当前已发布的视频资产`。

- 管理员统一配置外部可访问的 HTTPS 分享基址、准入账号／组、可分享根、自动替换规则与分享策略。分享地址按下述流程自动预填候选、管理员确认一次；分享入口可能与 App 的内网 NAS 登录地址不同，候选不能未经确认就用于对外链接。
- 创建、管理分享和更换播放版本分别授权；普通读取、上传收尾、文件改名权限不自动包含对外分享或替换他人分享内容的权限。
- 每条分享可配置免登录或登录后观看，并提供链接播放次数、有效时长及登录账号的观看进度和播放时间，访问控制与统计口径见第 6.3 节。
- Docker 按管理员确认的基址返回完整分享 URL，App 直接复制，不根据各同事当前连接的内网地址重新拼接。全局签名密钥留在 NAS，分享的过期、提取码、撤销及访问范围以服务端记录为准；具体默认值待冻结。
- 独立网页首版采用 App 风格的单视频播放器，包含倍速、长按加速、进度拖动、缩放及本地观看进度，具体交互见第 6.1 节；下载入口按策略开放。页面、错误及辅助功能文案覆盖简体中文、香港繁体中文和英文。媒体与页面资源由 NAS 提供，浏览器不支持的视频格式明确说明，不以创建分享自动转码。
- 分享链接使用不透明访问凭证，不暴露 NAS 凭据或宿主绝对路径，不将普通文件读取代理直接作为公共任意路径接口。公开播放接口与账号管理／写操作接口分开。
- 不复制整段视频来生成链接。映射与分享记录保存在持久卷；备份覆盖必要数据库、实例／根映射及密钥材料，升级不能重新生成既有视频 ID 和分享凭证。域名停用、到期、撤销或真实文件不可用等仍有对应失效语义。

### 2.1 对外分享地址：自动预填、管理员确认一次

采用“自动预填候选，管理员确认一次，所有同事统一使用”。确认与保存按 NAS 服务实例统一生效，同事无需逐人配置 DDNS 或分享地址。

1. **自动预填候选**：优先读取部署时提供的完整对外分享地址；没有时，可从已连接 NAS 的域名，或 NAS 在已授权、已验证接口中提供的 DDNS 配置生成候选。只有主机名时，HTTPS、端口及反向代理路径仍需补全；多个候选供管理员选择，无法获取时允许直接填写完整地址。
2. **管理员确认一次**：在 NAS 服务端设置页展示完整地址及来源，例如 `https://nas.example.com/nfm-share/`，由管理员核对证书、对外端口和路径后确认。校验 URL 格式与 HTTPS，拒绝包含账号口令、查询串或片段的基址，统一处理路径前缀与末尾斜杠。不将 WebDAV／NAS 管理端口自动认定为分享端口；普通同事及公开访问请求不能修改该配置。
3. **NAS 持久保存**：确认的基址保存在持久卷并纳入配置备份。重启、候选刷新及新的客户端连接不覆盖已确认值；后续只在管理员主动修改并确认后切换。反向代理地址只有在代理受信且配置明确时才可用作候选，不能直接信任任意请求的 `Host`／转发头。
4. **所有同事统一使用**：经授权创建分享时，Docker 使用这一基址返回完整链接，App 创建成功后复制。日常连接可继续走各自可用的内网／外网地址，分享链接仍统一使用管理员确认的公开入口，不要求同事另行配对或确认地址。

DDNS 只把主机名指向外部 IP，不包含分享服务的端口及代理路径；容器主机名也不是 NAS 的 DDNS 配置。跨品牌自动读取不能预先承诺，NAS 专用导入只是可选辅助，通用的完整地址设置始终可用；不通过扫描网络或 NFM 公共服务寻找地址。[Docker 网络与主机名](https://docs.docker.com/engine/network/#ip-address-and-hostname)、[NAS DDNS 配置示例](https://kb.synology.com/en-global/DSM/help/DSM/AdminCenter/connection_ddns?version=7)

实现时服务端可检查格式、DNS、TLS 与自身路由；实际外网可达性由管理员用外网设备验收，不将 NAS 本机可访问直接等同于外网可用。实际域名、端口、代理及证书尚未配置，此处仅描述交互与保存规则。

### 2.2 地址变化与旧链接

- 仅公网 IP 变化、DDNS 主机名和分享路由保持可用时，不需要修改已确认基址，现有链接继续使用原域名。
- 域名、端口或路径前缀变化时，管理员重新确认基址，新创建的链接采用新地址。已复制出去的链接不会随配置自动改变，需保留旧入口，或在仍受管理员控制的旧入口设置到同一分享的跳转；旧域名失去控制后不能保证旧链接恢复。
- 修改基址不重新生成视频 ID 或分享凭证，不延长有效期，也不恢复已撤销分享。地址迁移与视频资产换版分别核验。

## 3. 稳定视频身份与映射记录

建议采用下列最小关系模型，字段名为设计示例，不是已新增的公开 API。

| 记录 | 主要内容 | 保持稳定的含义 |
| --- | --- | --- |
| 视频记录 | `video_id`、管理域、可信上传归属（可未知）、当前发布资产、发布修订、状态 | 表示一段受管理视频，名字、路径、编码改变不直接改变此 ID |
| 文件资产／版本记录 | `asset_id`、所属视频 ID、根与当前路径、可用对象身份、文件版本、格式与核验结果、源资产／任务关系、命中规则及人工决定引用 | 记录实际原文件和后续压缩文件；原地改名可更新位置，新的压缩成品作为新资产 |
| 分享记录 | `share_id`、目标视频 ID、访问凭证及其安全保存引用、创建者、有效期、撤销、观看方式、允许观看范围、策略修订与统计配置 | 分享始终指向视频 ID，由视频记录解析当前发布资产；换版不自动延长有效期或恢复已撤销分享 |
| 观看统计记录 | 会话、账号／匿名归属、分享与资产版本、事件序号、观看区间、有效时长及聚合 | 账号与版本关联的已确认观看记录供授权统计查询，具体口径见第 6.3 节 |

示例中的 ID 仅作说明。

| 阶段 | NAS 实际文件 | 视频 ID | 当前资产 | 分享链接 |
| --- | --- | --- | --- | --- |
| 上传完成 | `/视频/活动.mov` | V-42 | A-1 | 同一个已登记链接 |
| 用户改名 | `/视频/活动最终版.mov` | V-42 | A-1，更新位置 | 保持不变 |
| 管理员完成并关联压缩版 | `/视频/活动最终版.mp4` | V-42 | A-2，核验后发布 | 保持不变 |

- 视频 ID 由服务持久生成，不从文件名、路径或内容摘要固定计算。压缩后字节与文件对象可能改变，不能依赖同一个哈希或 inode 自动贯穿所有阶段。
- 记录名称／路径历史用于核对和候选提示，旧路径不作为永久匹配规则；旧位置后来出现另一文件时，不能自动继承原分享。
- 首次登记来自已关联上传任务、首次创建分享时明确选择的现有文件，或管理员已启用监控中的视频候选。现有历史文件按需登记，不为本项全盘建立视频库。
- 视频管理权、原上传者、分享创建者与 NAS 文件属主分别记录；文件属主或“谁先点击分享”不自动成为修改映射的授权依据。普通复制默认是独立对象，不把字节相同的所有文件合并为同一视频。

## 4. 改名、移动与对象身份

| 来源 | 关联方式 | 处理 |
| --- | --- | --- |
| App／Docker 已确认的改名或移动 | 复用可信操作意图、源对象与执行结果 | 在确认实际对象及目标权限后更新位置，保留视频 ID；结果未知先核对，不盲目改表 |
| 其他客户端在同一可核验文件系统内改名 | 配对的移动事件、可用对象身份及版本等证据 | 证明是同一对象后自动更新，不仅根据新旧名字相似决定 |
| 跨卷／跨共享移动 | 已确认迁移任务的源与目标关系，或管理员确认 | 物理对象身份可能改变；无法建立可靠关系时保留待关联，不承诺任意外部复制删除均可自动追踪 |
| 同路径被删除后新建，或发现身份变化 | 对象与版本不再符合已登记资产 | 标为缺失／待核对，不自动把新文件接入旧链接 |

- 后端对象身份须带 NAS／存储命名空间，验证生命周期与复用边界。SMB 的可用文件索引与 WebDAV ETag 等版本信息需分别验证，不能把瞬时打开句柄 ID 当作跨会话视频 ID，也不能假设版本标记就是通用永久身份。
- inode 只在对应文件系统内唯一；网络文件身份信息的完整性取决于后端。支持相应 WebDAV 扩展时可评估 `DAV:resource-id`，不能假设所有 NAS 都提供。物理身份辅助核验，逻辑视频 ID 仍由 NFM 持有。[Linux inode](https://man7.org/linux/man-pages/man7/inode.7.html)、[Windows 网络文件身份说明](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileinformationbyhandle)、[WebDAV 资源标识扩展](https://www.rfc-editor.org/rfc/rfc5842.html#section-3.1)
- 移出授权根、文件权限变化或来源不明确时重新核验访问资格，固定视频 ID 不意味着可以跨越授权边界继续分享。

## 5. 压缩换版：覆盖可追踪任务与外部工具

### 5.1 首次本地压缩后上传

- 手机本地压缩成品进入原上传流程，服务为此次新视频登记 ID，完成 `.uploading` 提交后关联第一个正式资产。暂未成功的上传不发布为可播放视频。
- NAS 上没有原片时不建立“原片→压缩版”的虚假 NAS 关系，也不额外上传原片。之后重命名按第 4 节处理。
- 若以后增加明确的“替换这段视频的播放版本”入口，才在授权检查后携带现有 `video_id`／源资产关系；普通新上传不凭同名选择已有视频。

### 5.2 有明确源关系的处理

- 管理员可在处理前登记源视频／资产、预期输出与任务关系，或由已接入的压缩／处理任务携带源 ID。这里登记处理关系，不代表当前 Docker 已具备转码执行器。
- 外部脚本／工具若可接入，通过已认证、受限的完成回调报告任务和输出。服务再次核验任务归属、输出身份、目标权限及媒体完整性，不能仅信任输出文件附带的明文 ID 或任意回调路径。
- 来源可靠、结果核验完成且具备发布授权后，输出登记为同一视频的新资产并切换发布指针，保留原分享。新增资产与关系以任务幂等标识去重。

### 5.3 服务端规则自动替换

能通过可靠规则确定的自动替换，不能自动替换的在服务端提供手动功能。规则由管理员配置，不要求同事逐次确认，不将所有外部工具输出一律转人工。

| 证据／场景 | 默认处理 |
| --- | --- |
| 已验证源任务、预登记输出或可信完成回调，结果与权限核验全部通过 | 自动登记新资产并发布，保留视频 ID 和原分享链接 |
| 管理员已启用的明确输出约定，范围、可信来源、唯一对应及成品核验全部通过 | 按该规则自动替换；无需为每个文件重新配对或手动登记 |
| 只有同名 MP4、相近时长／大小，或仅部分命中规则 | 产生候选，进入服务端待确认列表，不静默改链 |
| 多个原视频／候选、其他视频已占用、来源或权限不明、核验失败 | 保留明确原因，转人工处理或等待文件就绪，不通过猜测提高命中率 |

- 管理员按源根／输出根、相对目录对应、文件名主体变换、来源扩展名和 MP4 输出等条件配置规则。可配置同目录或受控成品目录，但规则只能作用于已授权的范围，并保留版本、启停及操作人记录。
- 自动规则须有可信业务关系，例如已登记源任务，或管理员明确配置且可验证的受控输出约定。输出者／目录控制须经可靠证据确认，不能把同事任意可写的普通目录、一个文件属主或可伪造明文标记直接当作可信来源。
- 候选必须唯一对应目标视频，新文件未被另一视频占用，当前源／发布修订符合规则预期；完整写入、对象身份、媒体信息、目标权限和对外发布授权全部核验后才自动切换。跨目录重名、多个原片映射到同一 MP4 等情况转入人工。
- 时长、画面尺寸及媒体特征等仅作合理性检查和候选排序，不单独证明是同一内容；具体阈值用真实压缩样例冻结，不预设一个百分比承诺不会误关联。
- 在将事件产物作为独立新视频对外发布前，先完成规则／关联评估。未决候选不能因先建了另一分享记录而被错误抢占；已经归属另一视频的对象不自动合并或转移其分享。
- 发布记录保存来源证据、规则 ID／版本、源与目标资产及预期修订。规则停用、授权撤销或状态变化后重新核验，旧规则、重复事件和迟到回调不能覆盖更新的决定。
- 修改规则只重评已有候选或后续事件，不默认重扫历史文件；沿用“目录事件为主、日志辅助、非必要不补查”。对只有外部变化事件、缺少可信上传账号的文件保留身份未知，不接管为受限上传收尾任务。

### 5.4 NAS 服务端手动替换与历史回退

- **服务端管理页是已确认功能**，由 NAS 管理员或获授权的视频管理角色登录使用，与公开观看页分开。提供“待确认”“已自动替换”和视频版本历史，普通分享接收方的访问凭证不能管理映射。
- 待确认项呈现原视频、当前播放文件、候选 MP4、必要媒体信息和未自动替换原因，支持“替换播放版本，保持原链接”“保留当前版本”及在授权范围内另选文件。手动关联服务于同一视频的播放版本，不默认物理覆盖、移动或删除 NAS 文件。
- 管理员手动操作仍核验账号范围、对象身份、文件完整性和发布权限；仍在写入、损坏、越界或已归属其他视频的对象不能只靠点击确认强行接管。缺少关系证据可以由获授权管理员明确作出关联决定，但不能跳过其他必要检查。
- 提交前绑定当前发布修订与被选择的资产；成功后同事沿用原分享链接。保留人工决定与对象版本，针对相同／过期候选的自动处理不能再把它改回；后续新输出按现行规则处理，管理员可暂停该视频或规则的自动替换。
- 提供历史版本回退，仅在旧资产仍存在、核验可用且授权有效时切换指针；旧文件已删时明确不可回退，不声称能恢复物理数据，也不自动删除新旧文件。
- 自动与手动均记录操作者或规则、原因、前后资产、修订和时间，便于管理员核对；导出诊断继续脱敏。所有管理控件、状态、原因与辅助功能名称覆盖三语。

## 6. 发布切换、播放与失败语义

1. 新资产经过写入完成、身份、媒体完整性、必要播放兼容和权限核验前保持待处理，不改变当前已发布资产。
2. 自动规则与手动替换共用发布边界：文件侧完成后持久记录意图，再在数据库事务中按预期修订切换当前资产。改名、换版、撤销或规则变化时重新核对，较早事件／回调不能覆盖较新的人工选择；崩溃恢复核对文件与数据库之间的未决阶段，不假设两者天然具备跨资源原子性。
3. 新版本未就绪或失败时，原资产仍可访问则继续提供原版本；不自动删除原片。原片已经被外部删除时显示“等待关联新版本／暂不可用”，固定链接仍可解析，但不能承诺没有可读文件时仍能播放。
4. 一个播放会话固定实际资产及版本，ETag／Range 等按该版本处理，不把旧文件的前段和新 MP4 的后段混在一次播放中。新访问使用新的已发布资产；原播放资源已不可用时，通过同一分享链接重新加载，位置恢复按媒体实际情况处理。
5. 链接稳定不取消有效期、撤销、提取码或文件授权检查。换版不得复活已撤销分享，不通过“旧链接仍在”自动授予新资产对外可读权限。
6. 视频缺失、待关联、核验失败、权限变化与链接到期分别呈现三语状态。源被替换但归属未确认时保持明确状态，不悄悄播放其他内容。

### 6.1 App 风格网页播放器，首版范围已确认

2026-11-10 确认采用与 App 视频预览相近的视觉和操作方式。优先使用浏览器原生 HTML `<video>` 与自定义控制条，参考 App 的纯界面／手势逻辑，网页播放器不依赖 Tauri 或 App 的 NAS 凭据。当前仅确认设计，尚未实现或验证浏览器兼容性。

| 功能 | 首版交互 |
| --- | --- |
| 播放／暂停 | 明确按钮，点击未放大画面也可切换；默认由接收者点击后播放 |
| 进度控制 | 显示当前时间、总时长与可用缓冲范围，支持拖动跳转；未取得总时长时如实显示加载状态 |
| 倍速 | 提供 `0.5 / 0.75 / 1 / 1.25 / 1.5 / 1.75 / 2×`，初始 1×，显示当前已生效速度 |
| 长按加速 | 按住画面约 500ms 临时进入 2×，松手恢复此前选择的倍速，例如 1.5×；长按结束不误触暂停 |
| 全屏 | 按实际浏览器能力提供系统全屏或页面铺满，保留可达的退出入口与控制条，适配横竖屏及四边安全区 |
| 缩放 | 双指放大、放大后平移及复位；放大／平移时优先处理手势，不误触播放或长按加速 |
| 加载与失败 | 区分正常缓冲、网络／请求失败、格式／解码不支持和分享不可用；可恢复失败提供重试 |
| 音量 | 提供静音／取消静音入口，音量滑杆按浏览器实际支持启用 |

**布局与操作**

- 沿用两行悬浮控制条：第一行放播放、时间、音量、倍速、全屏，第二行放进度条；窄屏使用紧凑布局，避免按钮自然换行挤成三层。
- 播放时控制条可自动隐藏，触摸或鼠标移动时出现；暂停、菜单打开、控制条正在操作或键盘聚焦时保持可见。倍速菜单支持点击、键盘和关闭操作，不能只依赖 Hover。
- 进度条、控制按钮与菜单不触发画面长按。取消触摸、失去交互、切后台、换源或销毁时结束临时加速并清理手势；关闭菜单或缩放不能留下卡住的 2× 状态。
- 页面铺满与系统全屏分别呈现实际状态，页面铺满不承诺移除浏览器地址栏等系统界面。触控、键盘焦点及全部状态／辅助功能名称覆盖三语。

**播放与资源边界**

- 倍速通过浏览器播放速率完成，并在支持时保持音调；不为不同速度在 NAS 生成多份视频。NAS 继续按请求读取和发送，2× 播放会更快消耗视频数据，外网带宽与设备解码能力仍影响缓冲。[HTML 媒体标准](https://html.spec.whatwg.org/multipage/media.html#dom-media-playbackrate)
- 默认点击后播放，按浏览器策略处理播放请求被拒绝；“需要点击播放”与网络失败分别提示。采用内联播放并按能力切换全屏，iOS、Android 和内置浏览器分别验收。[WebKit 视频说明](https://webkit.org/blog/6784/new-video-policies-for-ios/)
- 控制条能力不改变浏览器的格式／编码支持。读取与重试沿用本节的资产版本隔离、过期和撤销规则；重试结束旧请求，尽量保留位置、播放意图及已选倍速，迟到结果不污染当前播放。

**当前浏览器的观看进度**

- 播放器在当前浏览器保存用于继续播放的位置，按分享与视频资产版本隔离，存储键使用资源标识。服务端观看统计按第 6.3 节采集会话与已确认播放区间，浏览器存储不可用时继续提供播放。
- 同一资产只是改名时保留进度；视频换版后先提供“从头播放／尝试继续”的选择，继续前核对新时长与可播放位置，不静默套用旧版位置。当前播放会话仍固定原资产，不因记忆进度混用新旧 Range。
- 进度记录不能绕过分享到期、撤销或权限检查，也不作为媒体缓存或文件身份依据。

### 6.2 NAS 不转码的分享网络优化，方向已确认

2026-11-10 确认面向低性能 NAS，分享优先直接分发原视频或已经生成的压缩成品，NAS 不执行视频转码。优化目标是减少无效传输、复看重复下载及并发峰值；同一份原视频完整观看所需的数据量基本固定，不将直传优化记为降低了视频码率，也不预设节省百分比。

| 措施 | 实施方向 | 收益与边界 |
| --- | --- | --- |
| 按需读取与 Range | 正确响应字节范围、`206`／`416` 及资产版本校验；按需读取并流式发送，播放器不先下载完整文件再播放 | 可直接定位所需片段，减少未观看部分和重复传输；完整观看同一版本仍需相应视频数据 |
| 点击后加载与请求取消 | 优先显示已有封面／媒体信息，播放前不自动拉取整段视频；关闭、切换视频及淘汰 Seek 请求时收尾旧读取与响应 | 减少“打开未看、只看几秒、反复跳转”造成的无效流量；取消不能收回已发出的数据 |
| 当前浏览器缓存复用 | 在访问策略允许时按资产与版本复用可缓存数据，避免仅因临时 URL 变化重复下载 | 同一浏览器复看可受益；首次观看、不同访客及浏览器已淘汰缓存不保证同样收益 |
| 播放并发与出口预算 | 管理员配置播放会话和服务总带宽预算，限制排队、预读及在途资源，适当给其他 NAS 操作留余量 | 控制峰值，不减少完整观看总量；带宽不足以承载媒体码率或倍速时仍会缓冲，限制值待实测冻结 |

- 浏览器的 `preload` 是提示，不能仅设置一个属性就宣称预读已被严格限制；实现时检查实际请求。暂停不等于关闭，不为节流反复清空缓冲或重置位置，切换／关闭才真正结束过期请求。[HTML 预加载说明](https://html.spec.whatwg.org/multipage/media.html#attr-media-preload)、[HTTP Range 规范](https://www.rfc-editor.org/rfc/rfc9110.html#section-14)
- 额度按播放会话与实例预算计量，不能只限制单个 HTTP 请求而被并行 Range 绕过；具体调度先验证不阻碍正常 Seek／取消，不照搬 App 的 SMB 读取槽位或扩大 App 并发。
- 缓存与第 6.1 节的观看进度分别处理。每个新播放会话仍核验分享状态与授权，换版隔离缓存；缓存命中不能跳过到期／撤销检查。不默认启用跨用户公开缓存或外部 CDN，也不承诺能远程收回已交付客户端的数据；响应缓存策略在实现时明确。
- 示例仅说明容量关系：平均 10 Mb/s 的视频，5 人同时以 1× 观看约需 50 Mb/s 上行，另有协议开销。2× 会更快消耗数据，限速和缓存不能自动降低媒体本身的码率。

**较小分享版本由手机／电脑提前生成**

- 要明显减少每次观看的数据量，优先使用 App 现有设备端压缩，或由电脑提前压缩一次，再把成品上传／放入 NAS。NAS 负责核验、映射和分发，不新增 NAS 视频转码执行器，也不要求同时上传设备原片。
- 首次压缩后上传按第 5.1 节登记实际成品；NAS 已有视频的后续较小版本按第 5.2～5.4 节，经过可信规则或服务端手动确认、完整性与权限核验后切换，保持原视频 ID 和分享链接，不凭同名自动接管。
- 若要求所有设备都不重新编码，收益主要来自上述传输与峰值优化。无损重封装可调整容器／轨道，不能据此承诺主要视频数据显著缩小；此处不新增自动重封装任务。[FFmpeg Streamcopy 说明](https://ffmpeg.org/ffmpeg.html#Streamcopy)

本节为已确认方案，尚未实现、部署或测得实际带宽收益。保持 NAS 自托管及既有分享授权边界，实际结论由真实网络和设备验收确定。

### 6.3 分享登录配置与观看统计

2026-11-12 新增每条分享选择免登录或登录后观看的需求，配套播放次数和时长统计。登录后可按已验证账号查看播放时间、有效观看时长、实际内容覆盖率及完播状态。

指标草案按实际播放进展登记播放次数，真实经过时间计观看时长，已播放区间合并后计完播进度。倍速、多次续看、并发、登录切换和视频换版分别保留可核对的会话与版本信息。访问方式变化时重新校验页面与媒体权限，统计采用 NAS 本地的有界采集、聚合和持久化。

登录来源先按复用已验证 NAS 账号起草，完播门槛、上报间隔和保留策略待确定。断网或强退导致的待补报／中断状态在统计页呈现，详细口径和验证安排集中维护。[登录与观看统计计划](video-analytics.md)

## 7. 实施与验证安排

- 先用模拟存储验证视频、资产、分享及观看统计记录、稳定 ID、位置更新、源任务关系、事务修订与缺失状态，再接入 NAS 后端。模型与接口先在独立模块验证，不扩大公开 VFS 序列化或修改现有连接结构来冒充已支持。
- 接入 App 上传登记和现有改名／移动结果；本地压缩流程不迁移到 NAS。实现经授权创建分享、剪贴板及第 6.1 节的 App 风格网页播放器，并按第 6.2 节接入不转码的有界直传；管理分享及换版作为独立权限。
- 接入事件驱动的位置核对、服务端规则自动替换及 NAS 服务端管理页的手动替换、忽略和历史回退；保持监控策略，不因为找不到某个视频就默认搜索全部共享，也不长期持有预览／监控句柄阻碍文件操作。
- 按逻辑提交运行受影响检查，最终关卡按[路线图](roadmap.md)合并。文档修改不启动 App／Docker／云构建；界面、触控、公开播放与实际 NAS 行为由用户验证。

重点自动用例：

- 登录／免登录访问、账号／组范围、策略切换、页面与媒体 Range 权限，覆盖到期、撤销及账号切换。
- 观看统计覆盖播放会话去重、倍速与真实时长、Seek 后的区间并集、多次续看／并发、内容换版、事件补报、断网／强退和统计查询权限，具体口径见独立计划。
- 直传路径不触发视频转码；验证合法／非法 Range、边界与版本变化、流式读取、取消及在途资源释放，不能先把整段视频读入内存或下载完整后才播放。
- 覆盖播放前加载、短看退出、重复 Seek、过期请求取消、同资产复看与换版缓存隔离；缓存不可用仍可正常取流，新的会话不能因缓存跳过分享核验。
- 并行 Range 共用播放会话／出口预算，覆盖并发、队列取消、慢客户端和高倍速，不无限积压请求或将限速误报为更低媒体码率。
- 播放器倍速选项与实际速率同步；从 1.5× 长按进入 2× 后恢复 1.5×，覆盖松手、取消、后台、换源和销毁；缩放／控制条操作不误触加速或暂停。
- 菜单打开／键盘聚焦时控制条不自动消失；播放受限不误报网络失败；重试取消旧请求、保留当前播放意图，旧事件不能覆盖新状态。
- 本地进度按分享与资产版本隔离，同资产改名保留、换版先询问、时长不符和存储不可用可退回正常播放；到期／撤销不能因本地进度恢复访问。
- 地址候选缺失／多个、内网地址与公开入口不同、同域名不同服务端口、代理路径前缀及 HTTPS 证书失败；未确认不得生成可复制分享链接。已确认配置经重启保持，候选变化或不可信请求头不能覆盖；域名／端口／路径迁移分别核验新旧入口，视频 ID 与凭证不变。
- 首次压缩成品上传只有一个视频 ID／初始 NAS 资产；临时文件提交、编号与普通改名不重建分享；旧路径被重用不误关联。
- 可靠文件身份下外部改名、身份缺失、对象替换、跨卷已登记迁移、事件丢失及有界补查；未知上传者不猜测。
- 源任务明确和管理员可靠输出规则全部通过时自动换版；未命中／部分命中进入待确认列表，不同目录同名、同目录多原片、来源不可信、同名同长但无可靠关系等均不静默接管。规则修改只重评已有候选或后续事件，不自动全盘查找。
- 服务端手动替换与保留当前版本、旧文件存在／已删除时的历史回退、无管理权限访问、重复确认、规则暂停／变化及迟到事件不得覆盖人工结果；手动操作不跳过完整性、范围和授权检查。
- 未完成／损坏输出不发布，原片保留与已删除两种情况、重复回调、写入与核验竞争、发布中断、并发替换与撤销均有明确结果。
- Range／Seek 不混合新旧资产，旧会话资源消失可重新解析同一分享链接；过期与撤销不因换版改变；映射更新、备份恢复与服务重启保持已确认 ID／凭证。
- 创建分享、替换版本、公开读取与上传收尾权限分离；越出授权根、身份变更及伪造源关系不能扩大公开访问范围。

网络对照保持 NAS、账号、视频版本、观看区间和网络条件一致，记录首次播放、短看退出、反复 Seek、同浏览器复看及多人并发的 NAS 实际发送字节、读取量、请求数、首帧／Seek 等待、CPU 和内存。浏览器缓存被淘汰、换版及手机／电脑预压缩成品分别记录，不把较小文件的收益算成相同原视频的传输算法提升。

播放器视觉与交互由用户在 iOS Safari、Android 浏览器及实际使用的内置浏览器验收：窄屏两行控制条、七档倍速、长按恢复、缩放／平移、音量与全屏能力、横竖屏／安全区、慢网 Seek、重试及换版后的进度选择。自动逻辑检查不代替浏览器实际表现，分别记录支持与降级结果。

用户验收重点为：普通／本地压缩后上传，分享后在 App 或其他客户端改名，管理员外部压缩后可信任务／规则自动替换和服务端手动替换两条路径，以及规则启停、歧义、人工决定保护、原片保留／删除、历史回退、服务重启、同名冲突及手机浏览器 Seek。记录“链接不变”“文件关联正确”“实际播放正常”三个独立结果，不以数据库命中替代完整验收。
